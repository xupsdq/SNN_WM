# 主图迭代修改通用流程

## 状态与适用范围

- 版本：`v1.4`
- 经验来源：Fig.1–Fig.4 的完整修改循环与图型／布局讨论
- 适用范围：Fig.2–Fig.6 及后续主图、补充图的交互式修改
- 核心原则：先形成可讨论的基础方案，再持续记录反馈；只有在用户确认修改清单后才实施
- 权威顺序：用户最新明确意见 > 单图科学契约 > 本通用流程 > 通用绘图默认值

本文件提炼的是可迁移的决策方法，不是 Fig.1 视觉元素的模板。不得把 Fig.1 的 85%–95% 强调带、50 ms 时间窗、100% 堆叠柱或具体颜色机械复制到其他图；只有证据结构和用户意见共同支持时才能使用相同编码。

## 1. 每张图开始时必须主动提供的基础方案

在用户给出具体修改建议之前，先检查单图契约、最终统计 CSV、当前绘图规格和当前成图，然后一次性提供以下内容：

1. **整图唯一问题**：这张图只回答什么问题。
2. **主要结论**：读者按面板顺序能够形成的、证据范围内的结论。
3. **论证链**：每个面板承担的前提、核心证据、机制证据或因果证据。
4. **数据边界**：来源、独立重复单位、过滤条件、排除项、单位和统计状态。
5. **当前版本诊断**：哪些图型、坐标、参照线、文字、图例或布局削弱了结论。
6. **基础修改方案**：逐面板给出默认图型、横纵轴、参考元素、颜色、标注、图例和布局。
7. **建议保持不变的部分**：避免为了全图统一而无意义地改动已经有效的面板。
8. **待用户增删的项目**：把基础方案作为讨论起点，不把它冒充最终决定。

基础方案必须足够具体，使用户可以直接说“保留、删除、改成什么”，但在用户确认前不得修改正式图。

## 2. 基础方案的逐面板记录格式

每个面板至少记录：

| 字段 | 要回答的问题 |
|---|---|
| `claim` | 面板支持的最小结论是什么 |
| `comparison` | 读者需要比较哪些量 |
| `evidence` | 数据来源、过滤条件和独立重复单位是什么 |
| `current_issue` | 当前画法为什么削弱阅读 |
| `chart` | 什么图型最匹配证据形状 |
| `x_axis` | 横轴变量、顺序、范围和单位 |
| `y_axis` | 纵轴变量、范围和单位 |
| `references` | 哪些零线、机会线、阈值或事件边界真正必要 |
| `annotation` | 最多保留哪些直接数值或符号 |
| `legend` | 图例属于面板、比较组还是整图 |
| `keep` | 哪些元素明确保持不变 |

## 3. 听取建议时的记录规则

用户反馈按四类记录，不立即混成代码改动：

1. **科学口径**：结论、比较对象、分母、条件、时间窗、单位。
2. **图型编码**：点、线、森林图、组成图、热图、示意图及其映射。
3. **视觉样式**：颜色、线型、标记、强调带、参照线、数字标注和图例。
4. **布局结构**：画布、面板槽位、数据区、装饰空间、轴线和图例对齐。

每条意见标记为：

- `confirmed`：用户已明确确认；
- `pending`：尚需继续讨论；
- `rejected`：用户明确否决；
- `superseded`：被后续意见覆盖。

回复时只做简洁复述和必要的证据核对，避免用户每提出一条建议就启动一次绘图。若新意见与既有确认项冲突，应指出冲突并以最新明确意见为准。

### 3.1 反馈作用域与抽象层级

每条反馈除状态外，还必须记录 `scope`：

- `panel_local`：只作用于明确点名的面板；
- `figure_local`：只作用于当前整图；
- `cross_figure_principle`：可迁移到后续图的抽象原则。

默认规则是：**具体操作一律先视为 `panel_local`**。只有用户明确说明适用于整图／后续所有图，或同一问题经独立检查在多个面板重复成立时，才允许扩大作用域。不得因为用户否决某一面板中的森林图、柱图、强调带、图例或标注，就自动改变其他面板或后续图。

从局部反馈提取通用经验时，必须完成三层转换：

1. **具体操作**：用户要求在什么面板删除、增加或替换什么；
2. **局部问题**：该操作试图解决什么阅读或证据映射问题；
3. **抽象原则**：不绑定具体图型、颜色、数值或面板的决策原则。

例如：

- 具体操作：在 c、d 不使用当前森林图；
- 局部问题：当前视觉标记与指标含义之间的映射不清楚；
- 抽象原则：为每个面板选择能让读者明确识别“比较对象—指标—证据”的编码。

抽象原则不是“后续少用森林图”或“所有结论都必须用柱图直接展示”。森林图、柱图或其他图型在别的证据结构中仍可能是正确选择。

在把一条经验写入本通用文件前，执行反例检查：如果它会无条件排除一个在其他面板中科学上合适的图型或布局，则说明它仍是具体操作，不是通用原则。

### 3.2 面板原子性与内部拆分确认门槛

用户已明确把以下要求设为后续所有 figure 的跨图原则：

- 一个 panel letter 默认对应一个完整、连续的视觉与坐标单元；
- 不得擅自把一个 panel 再拆成上下、左右、嵌套或 inset 的多个小图；
- 即使代码层面只创建一个 `Axes`，如果视觉上形成多个各自独立读取的
  局部坐标区、轨道、基线或小图，也视为内部拆分；
- 多个条件、指标或系列应优先在一套明确坐标语法中整合为类别、系列、
  轨迹、矩阵或组成，而不是无字母地塞入多个 micro-panels；
- 图例、色条和科学参照标记属于装饰或尺度成员，不等同于子图；
- 如果不同量纲、分母或尺度使单一坐标编码确实会产生科学误读，应先
  报告冲突和可选方案；只有用户对该 panel 的内部拆分作出明确确认后，
  才允许例外实施；
- 不得因为“更容易排版”或“一个图放不下”自行触发例外。

因此，任何基础修改方案在建议内部子图、分面、嵌套坐标或 inset 前，
都必须把它列为待确认的结构性例外，不能作为默认方案直接冻结。

## 4. 证据能力先于画法

在承诺某种显示前，先确认持久化数据是否支持：

- 能从既有 CSV 直接聚合时，只做 plot-only 统计和绘图；
- 只有粗时间窗统计时，不得插值伪造更细时间轨迹；
- 只有汇总值时，不得逆向制造 trial、network 或时间点；
- 组成图必须使用互斥且穷尽的类别，并明确分母；
- 配对线只能连接真实配对且分母一致的观测；
- trial、cell、coordinate 或 event 不得冒充独立 network 重复。

若所需显示超出现有证据：

1. 明确报告缺少的最小数据产品；
2. 给出不新增计算的替代画法；
3. 如确有必要，说明最小重放范围、父结果保护和验证方案；
4. 只有用户明确授权后才运行；
5. 新派生结果写入独立目录，不覆盖既有父结果；
6. 用既有粗粒度统计或其他独立结果验证新数据的一致性。

## 5. 图型与坐标的通用选择

- 有序 seed、时间或阶段：优先点线轨迹。
- 条件 × 单端点：优先网络级点范围或配对点。
- 条件 × 多端点：优先同一量纲轴上的森林图或对齐多行图。
- 总和为 100% 的互斥组成：使用实色堆叠组成图。
- 二维矩阵：使用带就近色条的热图。
- 示意图：只定义协议、方向或对象，不提前放入结果。

坐标和标注遵守：

- 使用变量的实际单位；用户已确认 manuscript-facing 图面统一使用 `%`，不显示
  `pp`。底层 contrast 仍保留精确的 percentage-point difference 统计语义和
  单位元数据，不进行数值重缩放；
- 横轴优先使用实际时间、seed 或实验量，而不是可被实际量替代的模糊类别；
- 只保留改变解释的参照线；不相关或远离数据的 chance line 可以不画；
- 背景强调带必须有明确语义，但图内可以不写文字；
- 数值标注最多保留两个最重要端点或组成，不用数字覆盖全部数据；
- 不在图内写标题、完整结论句、样本量或方法说明。

## 6. 毫米级布局先于局部美化

每张图先冻结：

1. 最终画布尺寸；
2. 每个面板的 `slot_bbox`；
3. 每个数据区的 `plot_bbox`；
4. 左、右、上、下装饰空间；
5. 需要对齐的轴线、图例和面板标签。

对于上下排存在对应列的布局：

- 先对齐槽位边界；
- 轴角色和装饰结构相同时，再对齐数据区；
- 同一行的 x 轴基线应处于相同全局高度；
- 同一列的 y 轴应处于相同全局位置；
- 坐标标题、刻度和图例必须完整留在所属槽位，不能串入相邻面板；
- 图例高度必须预留，不能在绘图完成后覆盖数据。

不得为了表面对称强制不相关面板共享尺度，也不得通过压缩某个数据区换取无意义的四边对齐。

### 6.1 语义分组与非对应行

- 先把面板组织为前提、后果、机制验证或边界条件等语义组，再决定每排放置
  哪些面板；不得从“每排放几个”反推科学关系；
- 连续回答同一反事实的证据链应优先保持邻接。拆分证据链必须有更强的直接
  比较或自然几何理由，不能只为形成对称网格；
- 上下排只有在承担对应语义角色时才建立对应列。若两排语义结构不同，可以
  不建立跨排对应列，但这不构成任意改变同一行列宽的理由；
- 减少空白优先通过重组 slot、调整画布行数和画布高度完成，不得以缩小字体、
  删除必要坐标轴或压缩数据区作为代价。

### 6.2 主图网格等分硬约束

用户已将以下要求确认为后续所有 figure 的跨图硬约束：

- 多行主图的各行必须等高；不得根据“某一行内容更丰富”“热图需要更高”或
  “一维估计更扁”等判断自行分配不同的行高；
- 同一行默认使用等宽分栏；不得根据连续阶段数量、标签长度、热图色条或主观
  的“自然几何”自行给某个面板更宽的 slot；
- 面板内容差异优先通过统一网格内的 `plot_bbox`、装饰留白、刻度抽稀、图例位置
  和整图画布尺寸解决，不能先改变 slot 的等分关系；
- 只有等宽会实质破坏必要证据的可读性、且上述内部调整均不能解决时，才允许
  把不等宽作为结构性例外提出；必须先说明不可替代的科学理由并获得用户明确
  确认，不能由绘图者直接实施；
- 各行面板数不同时，每一行仍在自己的可用宽度内等分。是否建立跨排对应列由
  语义关系决定，但不影响“行等高、行内等宽”的默认规则。

以上规则约束几何分配，不规定具体面板组合；语义分组仍先于排版，但不能被用来
绕开等高和等宽要求。

## 7. 确认与实施门槛

当用户表示“没有更多建议”时，先返回一份冻结修改清单，按以下结构汇总：

- 整图结论与阅读顺序；
- 各面板确认的图型、坐标、单位、参照和标注；
- 明确保持不变的面板；
- 精确画布、槽位、数据区和对齐关系；
- 数据来源、过滤和独立重复单位；
- 是否需要新增派生数据及其授权边界；
- 验收项目。

只有用户明确确认这份清单后，才进入代码、统计和正式成图修改。

## 8. 实施后的固定验证

### 数据与统计

- 编译所有修改文件；
- 核对行数、唯一主键、cohort、过滤和单位；
- 从 plot CSV 重建统计摘要；
- 若新增派生数据，与原有独立统计进行一致性复核；
- smoke 或单 seed 只验证结构，不作为正文证据。

### DAG 与父结果

- 统计构建使用 canonical task；
- plot-only 只读取最终 CSV 和登记资产；
- `--reuse-artifacts require` 缺失或损坏父级时必须明确失败；
- 比较 `parent_hashes_before.csv` 与 `parent_hashes_after.csv`；
- 不覆盖父数据、checkpoint 或既有正式结果。

### 视觉与导出

- 在最终毫米尺寸下检查整图；
- 分别检查每个 panel QA 裁图，防止轴标签跨槽位；
- 检查彩色与灰度版本；
- 检查 PNG 像素尺寸、PDF 单页尺寸和 SVG 可编辑文字；
- 检查图例、数字、阈值线、色条、裁切和碰撞；
- 连续两次 plot-only 复绘并核对正式 PNG、PDF、SVG 的确定性。

## 9. 迭代循环

每张图使用同一循环：

`读取证据与当前图 → 给出结论和基础修改方案 → 记录用户增删 → 汇总冻结清单 → 用户确认 → 实施 → 验证 → 展示新图 → 继续下一轮`

若用户对新图仍有意见，回到“记录用户增删”，只修改新增确认项；不要重新打开已经确认且未被覆盖的决策。

## 10. 交付与回退

- 正式输出保留 PNG、PDF、SVG 和 panel QA；
- 统计、source manifest、布局测量和验证报告随图保存；
- 替换旧图前建立可恢复备份；
- 当前图尚未被用户最终接受时，将备份显式标记为 `KEEP`；
- 清理 smoke、转换测试和无用草稿；
- 最终回复说明正式图位置、验证结果及仍保留的回退副本。
